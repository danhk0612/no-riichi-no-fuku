현재 세 축만으로 **성향 표현을 유지하는 10개 강도 구간을 설계할 근거가 부족하다**. 제품 채택표/최적 조합은 만들지 않았다. 최대값 선택은 중립·혼합 상대에서 개선 경향이 있지만 성향 상대에서는 평균 점수와 순위 방향이 충돌하고, 공통 입력에서 버림패의 성향 차이가 거의 사라졌다. 수용패수/위험 축의 효과는 작거나 상대 구성에 따라 방향이 달랐다.

## 공통 관측·성향·비용

새 seed1701 공개관측160개×8성향×8조합=10,240입력을 **두 독립 프로세스**에서 검사했다. 전체 행동/후보/진단값(시간 제외)이 일치하며 결정적 SHA256은 execution.json에 있다. 합법성·대조행동/RNG·기존 성향6값/계수·원 비discard/fold 보존 gate를 통과했다. gate의 성향 기준은 캐릭터 간 행동 차이 존재이며, 전반적 성향 표현/비율 보존을 뜻하지 않는다.

## 재현·회귀·한계

- 두 gate 프로세스 전체 결정적 자료 일치, 3context×9조합 seed2000 좌석2 **27대국 전체 trace/결과**를 독립 프로세스에서 재현했다. 추출은 결과를 보고 고르지 않았다.
- 8조합 seed1811에서12개 사람 action index를 JSON 저장/재생한 뒤 남은 35~70턴의 모든 human-turn hash와 최종결과가 일치했다. 변경 현재설정을 실제 전달해 저장profile 우선/새대국 변경profile 적용을 확인했고 unknown/변조profile을 거절했다. factory 주입 격리 검사이며 production policy3/파일DB 복구 완료가 아니다.
- 기존 backend unittest129개94.656초·대사pytest10개0.12초, 연구 종료/deadline fault검사4개·알려진 factorial 집계검사1개 통과. 최초 unittest를 루트에서 실행해 alembic.ini 경로 오류1건이 났고 문서대로 backend에서 재실행해 통과했다. 제품은 수정하지 않았다.
- v1/v2 도구·모든 원본근거·Tier0/1/2·policy1/2/legacy fixture 및 나머지 기준 source의 blob hash 불변을 sources.json에 대조한다. 새 frontend/build/browser/Windows CI/artifact·실제 Windows·인간상대·화료/방총률은 미검증이다.
- 이 작은 진단 표본은 단조10단계/성향별 강도를 입증하지 않는다. 최댓값/위험 특징/휴리스틱 EV의 우월성, 특정 seed 모집단 일반화도 주장하지 않는다. 이미 사용한 표본을 새 holdout으로 부르지 않는다.

## 다음 판단과 재현 명령

현재 결과로10profile 후보를 추가 튜닝하거나 최대 평균 조합을 제품에 채택하지 않는다. U/D의 비단조·작은 효과와 M의 성향 축소를 함께 다룰 **판단 평가·후보 선택 설계 범위 재검토가 필요**하다. 별도 승인 후에만 성향 표현 수용 기준·점수/순위 목표·확장할 판단 범위·새 독립 검증 예산을 정한다. 새 선읽기/탐색·리치/울기/fold 변경은 이번 결론으로 승인되지 않는다. DIFF-* 정책과 W-DIFF-B는 계속 대기다.

새 깨끗한 checkout에서 선언 backend 의존성/RiichiEnv0.4.8을 설치하고:
```sh
python spikes/w-diff-a/decision-probe/test_deadline.py
python spikes/w-diff-a/decision-probe/test_analysis.py
# 새 실험 실행은 기존 근거를 덮지 않도록 중단되며 별도 승인 없는 재실행 금지.
# 승인된 새 실행에서만 evidence 없는 checkout으로 execute.py 실행.
python spikes/w-diff-a/decision-probe/analyze.py spikes/w-diff-a/decision-probe/evidence
```

원자료 gate1/gate2/matches는 결정적 mtime0 gzip의 JSON이며 `gzip.decompress`로 읽는다. 압축 전후 JSON 동일성을 확인했다. 분석은 plain/gzip 모두 지원한다. 원 journal hash·비교 jobs·완료/미실행수·source/evidence hash를 보존한다. `archive.py`는 성공한 새 실행의 전체 근거를 손실 없이 압축하고, 현재 보관 근거에 반복 실행하는 도구는 아니다.
